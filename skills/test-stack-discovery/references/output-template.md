# `.qa-skills/test-stack.md` — output contract

Other skills (automation, test review, environment access…) read this file by section title and Stack row name. Keep titles, order, fixed rows and markers **exactly** as below, always in English. Prose inside sections follows `report_language`. Don't add new top-level sections — put extra findings in the closest section. If a section has nothing to say, keep it with one line (`none found` + what you checked).

## Markers

| Marker | Meaning |
|---|---|
| `path:line` / `path` | Evidence. Paths are relative to the repo root. |
| `(observed N/M <unit>)` | Convention seen in N of M sampled items — say what was counted (`specs`, `tests`, `locator calls`). Not declared anywhere. |
| `⚠️ UNCERTAIN` | Couldn't be confirmed from the code. Always also listed under Uncertainties. |
| `none found` | Looked for it and it isn't there (say where you looked if it's not obvious). |
| `n/a — <reason>` | The row doesn't apply to this suite (e.g. headed mode in an API-only suite; starting the app in a tests-only repo whose app lives elsewhere — then cite where the URL is configured). |
| `(standard <tool> CLI, not documented in repo)` | A command row filled with the tool's own syntax because the repo doesn't document it. |
| `(confirmed by QA)` | The user confirmed or corrected it. Survives re-runs unless the code contradicts it. |
| `❓` | Open question for the user, in Uncertainties. |

## Filled example (excerpt, fictional repo)

```markdown
<!-- qa-skills:test-stack v1 -->
# Test stack

Generated by test-stack-discovery · 2026-03-14 · repo: /home/ana/work/shop-web · test module: e2e/

## Summary
Product repo (Next.js storefront) with a Cypress e2e suite in `e2e/` and Jest unit tests next to the components; this file focuses on `e2e/`.
UI tests use App Actions via custom commands; API calls stub or seed data through `cy.request`. Runs in GitHub Actions against a dev server started by `start-server-and-test`.
Node version isn't pinned locally (only in CI).

## Stack
| Item | Value | Evidence |
|---|---|---|
| Repo type | product repo with test modules (`e2e/`, colocated `*.test.tsx`) | `package.json:5`, `src/components/Cart.test.tsx` |
| Language | TypeScript 5.4 | `package.json:41` |
| Runtime / toolchain | Node 20 in CI; local version ⚠️ UNCERTAIN (no `.nvmrc`/`engines`) | `.github/workflows/e2e.yml:18` |
| Test framework(s) | Cypress ^13.6.0 (locked 13.6.4) | `package.json:33`, `package-lock.json:2810` |
| Lint / format | ESLint with `eslint-plugin-cypress`; Prettier (single quotes, no semicolons) | `e2e/.eslintrc.json:3`, `.prettierrc:2` |

## Patterns and conventions
### Selectors / locators
`data-cy` attributes only (observed 31/31 `cy.get` calls), wrapped in `cy.getByCy()` (`e2e/support/commands.ts:8`). No XPath, no CSS classes.
### Rules for new tests
- Put specs in `e2e/specs/<feature>/<feature>.cy.ts` (`e2e/specs/cart/cart.cy.ts`).
- Seed data with `cy.task('db:seed', …)`, never through the UI (`e2e/specs/cart/cart.cy.ts:6`).

## Reference tests
| Test | Why imitate it | Shows |
|---|---|---|
| `e2e/specs/cart/cart.cy.ts` | Changed last week; uses `getByCy`, `db:seed` and the `@smoke` tag like most specs | App Actions, seeding, tagging |

Don't imitate: `e2e/legacy/checkout_old.js` — plain JS with CSS selectors, excluded from CI (`cypress.config.ts:12`).

## Uncertainties / open questions
- ⚠️ UNCERTAIN local Node version — no `.nvmrc`, `engines` or `.tool-versions`; CI uses 20.
- ❓ Specs mix `describe('Cart')` and `describe('cart page')` title styles in equal numbers — which one should new tests use?
```
