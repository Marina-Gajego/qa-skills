# `.qa-skills/test-stack.md` — index contract

Other skills read this file first: it says which repositories and suites exist, how far the discovery got, what's covered and what's still open, and points to the session files (templates in [templates/](templates/)). Keep titles, order, fixed rows and markers **exactly** as below, always in English. Prose follows `report_language`. Don't add top-level sections — put extra findings in the closest one. If a section has nothing to say, keep it with one line (`none found` + what you checked).

## Markers (used in every file)

| Marker | Meaning |
|---|---|
| `path:line` / `path` | Evidence. Relative to the test repo; `product:path:line` for a separate product repo. |
| `(observed N/M <unit>)` | Convention seen in N of M items — say what was counted (`tests`, `specs`, `locators`, `page objects`). Not written down anywhere. |
| `(written: <path:line>)` | Rule stated in the team's docs, agent context file, PR template or lint config. |
| `⚠️ UNCERTAIN` | Couldn't be confirmed from the code. Always also listed under Uncertainties in the index. |
| `none found` | Looked for it and it isn't there (say where you looked if it's not obvious). |
| `n/a — <reason>` | Doesn't apply (e.g. headed mode in an API suite). |
| `(standard <tool> CLI, not documented in repo)` | A command filled with the tool's own syntax because the repo doesn't document it. |
| `(confirmed by QA)` | The user confirmed or corrected it. Survives re-runs unless the code contradicts it. |
| `❓` | Open question for the user, in Uncertainties. |

## Session files (`test-stack/*.md`)
One file per session (1–6), each with its own template in [templates/](templates/) — read a template only when you are about to write that session's file. Other skills open only the files their task needs (writing a UI test → `recipes.md` and `conventions.md` first). Every session file starts with its marker line and a header and has one `## Suite: <name>` section per suite holding that file's `###` subsections — keep the heading even with a single suite, so readers find things in the same place. Things shared by all suites go in a `## Shared` section before the suite sections. A subsection that doesn't apply stays with `n/a — <reason>`.
